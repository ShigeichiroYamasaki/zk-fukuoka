# 応用編：ERC-20送金用ZK rollupを作る

第1〜15回で学んだ証明系を，入金・送金・出金のあるシステムへつなげる6段階の開発教材です．単一のERC-20をL1に預託し，L2で送金し，状態遷移の証明をL1で検証する小さな構成を目指します．

更新日：2026年9月27日

[講義一覧](../learn/sessions) · [入出金の算術化](../exercises/session-04#program) · [演習](../exercises/)

::: info 教材の到達点と現在の配布物
このページ群は，実装仕様・開発手順・合格条件を揃えた応用編です．配布するコードは，残高台帳・Merkle木のPython参照モデルと，送金の算術部分を扱うCircom入門回路です．署名とMerkle検証を統合したrollup回路，L1ブリッジ，運営者停止時の退出は，各章で実装する課題です．完成したrollupやテストネットへのデプロイ済みシステムとして提供するものではありません．
:::

## 最後に実現する利用例 {#goal}

1. AliceがテストERC-20を100単位，L1の預託コントラクトへ入金する．
2. 入金キューを処理したバッチが確定し，AliceのL2残高が100になる．
3. AliceがL2の送金に署名し，Bobへ30送る．残高は70と30になる．
4. Bobが30の出金要求に署名する．L2残高は0になり，未請求の出金が30残る．
5. 証明がL1で受理された後，Bob宛ての出金を一度だけ請求する．
6. 公開データから別のノードが状態を復元でき，運営者停止時にも規定の退出手順を実行できる．

偽署名，残高超過，同じnonceの再使用，入金の二重計上，出金の二重請求を拒否することも完成条件に含めます．

## 最初の仕様を小さく固定する {#scope}

- 対応トークンは一つのテストERC-20．手数料付き送金，rebase，任意トークン対応は扱わない．
- 金額・残高・nonceは64ビット符号なし整数．ゼロ金額と自己送金は拒否する．手数料は0．
- アカウントは4個，IDは0〜3．初期登録でL1所有者アドレスとL2署名公開鍵を固定し，鍵更新・新規登録は発展課題とする．
- アカウント木の深さは2，バッチは4スロット．空きスロットは明示的なNOPで埋める．
- Circom＋circomlib＋snarkjsのGroth16，Solidity＋Foundryを使う．EVM命令の実行証明は範囲に含めない．
- 最初のデータ公開にはL1のcalldataを使う．署名付き操作と状態復元に必要な値を公開するため，送金情報の秘匿はこの教材の目標にしない．

ZK rollupには，妥当性証明に加えて状態を復元するためのデータ可用性が必要です．[Ethereumの解説](https://ethereum.org/developers/docs/scaling/zk-rollups/)を読み，証明だけをL1へ提出する構成との違いを確認します．

## 開発ディレクトリと前提知識 {#setup}

成果物はサイトのソースとは分け，自分の演習用ディレクトリで管理します．

```text
zk-token-lab/
  model/           # 状態遷移の参照実装
  circuits/        # 送金・入金・出金・バッチ回路
  contracts/       # Token, Rollup, Verifier
  operator/        # キュー取得，バッチ化，証明生成
  client/          # L2鍵と署名，入出金操作
  tests/           # 回路・コントラクト・E2E
  fixtures/        # 正規化した入力と期待値
```

Pythonとコマンドラインに加え，Solidityの状態変数・イベント・revert，ERC-20のapprove/transferFrom，JavaScriptのBigInt，ハッシュと署名の違いを確認してください．金額をJavaScriptのNumberへ変換しないようにします．

[基本操作マニュアル](../exercises/manuals#groth16)で証明生成まで一巡してから進むと読みやすくなります．使用したコンパイラ・ライブラリ・検証鍵の版を記録し，回路を変えたらR1CS・鍵・検証コントラクトを作り直します．

## 最初に動かす

[第1段階](./01-ledger#run)のPythonモデルは外部ライブラリ不要です．まず100→70/30→出金という流れを実行し，次に同じ処理を回路とL1へ分担させてください．
