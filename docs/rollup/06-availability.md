# 6. データ公開・停止時退出・総合テスト

[応用編](./) · [前：L1接続](./05-bridge) · [第14回](../learn/session-14)

## ルートと証明だけでは足りない

独立した利用者が状態を再構築できることを確かめます。初期アカウント登録，L1入金キュー，受理済みバッチの540バイト列，出金の確定と請求イベントを取得し，順番に再実行します。各バッチで計算したルートとL1の保存ルートが一致しなければ停止します。

初版ではcalldataとイベントへ同じバッチデータを公開し，回路とL1双方でそのハッシュを検査します。データをIPFSなどへ置き，ハッシュだけL1に載せる構成へ変更すると，同じデータ可用性の保証にはなりません。[Ethereumのrollup解説](https://ethereum.org/developers/docs/scaling/zk-rollups/)を参照してください。

## 独立復元ツールを作る

`operator/replay.ts`を，運営者のローカルDBを使わず動かせるようにします。設定ファイルにはチェーンID，コントラクトアドレス，開始ブロック，仕様バージョンを保存します。

1. 確定したL1ブロックだけを順番に読み，バッチ番号の連続性を確認する。
2. データを決められたビッグエンディアン形式で復号する。余分なバイト・不正なNOPを拒否する。
3. 署名，nonce，キュー，残高更新を再実行する。
4. アカウント木と出金木を再構築してルートを照合する。
5. 再開位置を保存し，L1再編が起きたら共通祖先まで戻す。

## 運営者が止まったらどうするか {#exit}

この教材の退出方式は，**期限後に永久凍結し，最後の受理済み状態から回収する**方式とします。凍結後の通常運転再開は扱いません。単に残高パスを提出していつでも出金できる関数を追加すると，通常送金との競合で二重回収を起こし得ます。

まず，初期登録で固定したL1所有者だけが自分のaccountIdについて退出要求を記録できる入口を作り，処理期限をL1ブロック数で固定します。期限は無関係なバッチを提出しても延長できないものとします。要求の解除は，要求者本人による取消し，または現在の受理済みルートに対する「そのアカウントの残高が0」という所属証明で行います。残高0なら通常出金の未請求分は別の出金ルートから回収できます。未処理の最古要求が期限を過ぎたら誰でも凍結できます。未処理入金の期限も設け，入金後にL2へ反映されない場合を扱います。

凍結トランザクションで，状態ルートと入金カーソルを固定し，以後の入金・バッチ更新を拒否します。回収先を次の三つに分けます。

| 回収対象 | 根拠 | 再使用防止 |
| --- | --- | --- |
| まだ処理していない入金 | 凍結カーソル以降のL1キュー | depositIdごとの返金済みフラグ。入金時に記録した返金先へ送る |
| 凍結時のL2残高 | 凍結ルートへのアカウント所属パス | accountIdごとに残高全額を一度だけ，葉のL1所有者へ送る |
| 受理済み・未請求の出金 | 既存の出金ルート | 通常と同じ請求済みフラグを使う |

L2残高からすでに引かれた出金を，凍結時残高としてもう一度払い戻してはいけません。初版でL1所有者の変更を許さない理由も，この回収先を明確にするためです。

`requestExit(accountId)`，`cancelExit(requestId)`，`resolveEmptyAccount(requestId, leaf, path)`，`freeze()`をL1に実装します。0残高の証明は要求のaccountId・所有者・現在のstateRootに結び付け，古いルートや別アカウントで要求を解除できないようにします。管理者による任意の解除は設けません。この簡単な方式は利用者の要求でシステム全体が永久停止し得る設計です。停止せず処理を強制する方式への拡張は別課題とします。

## 卒業制作の受入テスト {#acceptance}

| 試験 | 合格条件 |
| --- | --- |
| Alice 100入金→Bob 30送金→Bob出金 | 実Verifierが証明を受理し，L1のBobが30受け取る |
| 不正操作 | 偽署名，過剰送金，再送，二重入金，二重出金を拒否 |
| データ改変 | 証明と異なるcalldataを受理しない |
| 独立復元 | 新規DBから全受理済みルートを再現 |
| 運営者停止 | 期限後に凍結し，上の3種類の請求を重複なく処理 |
| 不正な延命 | 無関係バッチで退出期限を延ばせない |
| 凍結との競合 | 凍結後のバッチを拒否し，凍結直前の受理結果を正しく扱う |
| L1再編 | 未確定の入金・バッチを巻き戻し，再取得できる |

## 提出するもの

ソース，依存版，回路ハッシュ，検証鍵，セットアップの由来，正常系と異常系のテスト結果，独立復元ログ，運営者停止テストを揃えます。テストネットではチェーンIDとデプロイ先，使用トークン，実行トランザクションを記録します。

この教材の公開自体は，受講者が本体のE2Eを達成したことを意味しません。実資産へ進む前に，回路・ブリッジ・退出機構のレビューと監査，鍵・セットアップ・運用の検証を別途行ってください。
