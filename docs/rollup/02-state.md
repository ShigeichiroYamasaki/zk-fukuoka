# 2. Merkle木と状態ルート

[応用編](./) · [前：台帳](./01-ledger) · [次：送金回路](./03-circuit)

## 何をL1に残すか

台帳全体をL1の状態変数へ書く代わりに，アカウント木のルートを保持します。ただし，ルートだけから残高を復元することはできません。復元用データは[第6段階](./06-availability)で別に公開します。

4アカウントの木は，葉4個，内部ノード2個，ルート1個です。アカウントIDの2ビットで葉の位置を固定します。

## 葉の仕様を固定する

回路版では次のフィールドを順序付きでハッシュします。

```text
leaf = Poseidon(TAG_ACCOUNT, id, l1Owner, l2KeyX, l2KeyY, balance, nonce)
node = Poseidon(TAG_NODE, left, right)
```

タグは異なる固定定数とし，実装・回路・初期状態生成で共通にします。IDは2ビット，L1所有者は160ビット，残高とnonceは64ビットに制限します。L2鍵はBaby Jubjubの署名鍵で，Ethereumウォレットの鍵とは別です。

初期登録データを公開し，所有者とL2鍵の対応を確認してから，残高・nonceが0の初期ルートを固定します。この小さな教材では新規登録と鍵更新を許しません。後から所有者や鍵を任意に変更できる回路にしてはいけません。

## 所属と更新を一緒に確認する

一人のアカウント更新では，旧葉と兄弟ノードから旧ルートを再計算し，一致を要求します。同じパスで新葉を入れたルートを計算します。

送金では次の順序を守ります。

1. `oldRoot`に対する送金者のパスを検査する。
2. 送金者を更新し，`intermediateRoot`を得る。
3. **`intermediateRoot`に対する**受取人のパスを検査する。
4. 受取人を更新し，`newRoot`を得る。

二人の旧ルートに対するパスから独立に新ルートを作っても，両方の変更を含むことは保証されません。自己送金は仕様で拒否し，二つの更新が同じ葉になる分岐を初版から外します。

## 参照モデルで試す

```python
from ledger_model import Ledger
l = Ledger()
l.apply('receive', 0, 100)
l.apply('consume', 0)
old = l.root()
a = l.accounts[0].copy()
assert l.verify(a, 0, l.path(0), old)
a['balance'] += 1
assert not l.verify(a, 0, l.path(0), old)
```

Pythonモデルは構造を学ぶためSHA-256とJSONを使用します。回路版のPoseidonとは**ルート値が一致しません**。両者を接続する段階で共通のフィールド符号化へ置き換え，別途ゴールデンベクトルを作ります。

## 実装課題と合格条件

`operator/state.ts`に葉の符号化，木の生成，パスの生成，逐次更新を実装します。次をTypeScriptと回路の両方で同じ入力に対して確認してください。

| テスト | 期待結果 |
| --- | --- |
| 全4葉のパス | 初期ルートと一致 |
| 兄弟ノードの左右を交換 | 拒否 |
| 葉のbalance・owner・鍵・IDを一つだけ変更 | 拒否 |
| 送金後に旧パスを再利用 | 必要な箇所で拒否 |
| 二人の更新 | 木全体を再計算したルートと一致 |

[Poseidon回路の公式ソース](https://github.com/iden3/circomlib/blob/master/circuits/poseidon.circom)を参照し，実装の版とパラメータを固定します。
