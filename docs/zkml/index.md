# 応用編：入力を隠したAI推論を検証する ZKML

更新日：2026年9月27日

AIが出した答えを使うとき，「どのモデルで計算したのか」を確認したいことがあります．一方で，計算に使った入力は相手に見せたくありません．この二つの要求を，小さな機械学習モデルとGroth16で両立させてみましょう．

この実装例では，2個の整数を入力とする分類器をPythonで学習し，その推論をCircomの回路にします．証明者は入力を自分の端末に保持し，検証者には分類結果と証明だけを渡します．

## 何を証明するのか

公開されたモデルを $f$，秘密の入力を $x$，公開する分類結果を $y$ とすると，証明する関係は次のようになります．

$$\exists x\in\{0,\ldots,15\}^2:\quad y=f(x)$$

| 対象 | この実装での扱い |
| --- | --- |
| モデルの重み・バイアス | 公開．回路の定数として固定する |
| 入力 $x$ と中間計算 | 非公開のウィットネス |
| 分類結果 $y$ | 公開．0または1 |
| 証明する計算 | 学習済みモデルの推論 |
| 学習処理・データの出所 | 証明の対象外 |

::: info この例の意味と限界
まず「ある秘密の入力に対する推論」を証明する最小例です．外部の測定記録や利用者の本当のデータとの結び付けはありません．証明者は好きな入力を選べるので，このままでは本人の資格や実際の測定結果を証明する用途には使えません．[実システムへの拡張](./02-proof#next)で入力のコミットメントや署名との結び付けを考えます．
:::

ゼロ知識性は「公開した分類結果から分かる情報まで消す」という意味ではありません．結果そのものや，何度も問い合わせた結果から推測できる情報は残ります．また，入力を外部サーバへ渡して証明を生成させれば，そのサーバには入力が見えます．本例ではローカルで証明を生成します．

## 学習の順序

1. [モデルの学習と算術化](./01-model)：整数の分類器を学習し，符号判定をビット制約に変換する．
2. [証明生成・検証の操作マニュアル](./02-proof)：配布コードを実行し，正しい証明の受理と改ざんの拒否を確認する．
3. [実システムへの拡張](./02-proof#next)：入力の真正性，量子化，ニューラルネットワークへの発展を整理する．
