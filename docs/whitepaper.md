# ホワイトペーパー

**ステータス：提案 · v0.1 · 2026年9月24日 · 最終更新：2026年10月12日**

設立に向けた議論のための初期草案です。組織の設立完了やイベント開催の確定を示すものではありません。

## 目的

ZK Fukuoka は、ゼロ知識証明を技術として学ぶこと自体を目的にするのではなく、現実の課題に適用できる技術者を育てる、福岡を拠点とするコミュニティの構想です。参加者が課題の性質を見極め、ゼロ知識証明が適切な解決手段かを他の方法とも比較したうえで、必要な数学を理解し、設計・実装・検証まで進められることを目指します。

## 実課題への応用を重視する

プライバシーを保ちながら計算の正しさを確かめたい場面や、計算結果を第三者が検証できるようにしたい場面などを題材に、ゼロ知識証明が何を解決し、何を解決しないのかを学びます。ロールアップ、入力を隠した推論の検証、データ最小化などの応用例を通じて、課題の定義、方式の選択、プロトタイプの構築、テスト、限界の評価を一続きの学習として扱います。性能・安全性・可用性・法令や運用上の要件も検討対象とし、ゼロ知識証明をあらゆる問題に当てはめるのではなく、適切な場面で使える判断力を養います。

## 大切にすること

- 前提知識より好奇心：質問と失敗から学べる場をつくる。
- 手を動かす学び：輪読、演習、小さなプロジェクトを組み合わせる。
- 開かれた知識：教材と意思決定の記録を GitHub で管理し、日英で発信する。
- 適切な位置づけ：学習用の試作と、実運用できるシステムを区別する。

## 活動案

[シラバス](./learn/)を共通の学習経路として、勉強会、実装ワークショップ、成果発表を計画します。毎回の振り返りを次の活動に反映します。開催頻度、会場、講師、オンライン参加の方法は今後決定します。

## 運営案

まずはメンテナーと貢献者が Issue・Pull Request を通じて改善をレビューする形を想定します。重要な決定は、背景・代替案・影響とともに [ADR](./adr/) に記録します。役割分担、決定権限、運営ルールは今後合意する提案事項です。

## 目指す学習成果

証明の性質を説明できることに加え、現実の課題を技術要件に整理し、ゼロ知識証明を使う理由と代替手段との違いを説明できることを目指します。例題や小さなプロトタイプを再現・実装し、テスト結果と限界を評価できることも重視します。再現性、つまずき、相互レビューの質を改善の手がかりにします。数値目標は未設定です。教材内の実装例は学習用であり、実運用には個別のセキュリティ評価や法務・運用面の検討が必要です。
