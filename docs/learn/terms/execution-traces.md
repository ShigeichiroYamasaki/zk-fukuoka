## 計算の途中を表に残す

**状態**は，次の処理に必要な値の組である．その状態を時刻順に並べた表が**実行トレース**である．単なる画面の実行ログと違い，AIRでは検査に必要な値が決まった列に配置される．

$\mathbb F_{101}$ 上で $a_{i+1}=a_i^2$ を3回繰り返し，$a_0=2$ から始める．

| 時刻 $i$ | 状態 $a_i$ |
| --- | --- |
| 0 | 2 |
| 1 | 4 |
| 2 | 16 |
| 3 | 54 |

最後は $16^2=256\equiv54\pmod{101}$ である．状態を一列にした小さな例だが，実際のトレースには命令位置や複数のレジスタなども並び得る．

## 二種類の制約を分ける

遷移制約は $a_{i+1}-a_i^2=0$ を $i=0,1,2$ で要求する．最後の行には次の行がないので，同じ遷移を無条件に課さない．

境界制約は $a_0=2$ と $a_3=54$ である．正しい遷移だけなら，出発点3からの別の列も許してしまう．境界だけなら，中間値を誤っても気付かない．両者を組み合わせて，指定された実行を固定する．

## 表から多項式へ

相異なる評価点 $d_0,\dots,d_3$ を選び，$T(d_i)=a_i$ となる多項式を補間する．乗法的な評価領域 $d_i=g^i$ なら，隣の行は $T(gX)$ で参照できる．遷移式は $T(gX)-T(X)^2$ となり，遷移を要求する点で0になることを検査する．

ただし，評価領域の選択，最終行の除外，次数の上限は別途定める．たとえばこの体では $g=10$ が位数4を持つので点 $1,10,100,91$ を使えるが，循環して初期行へ戻る遷移はこの例では要求しない．表があるだけでSTARKになるわけではなく，コミットメントや低次数の近接性検査も必要になる．

## 確認問題

トレースを $2,4,17,54$ に変えたとき，境界制約と遷移制約はどうなるか．

::: details 解答
両端は変わらないので境界制約は満たす．しかし $17-4^2=1$ なので，時刻1から2への遷移が失敗する．時刻2から3も $54-17^2\not\equiv0\pmod{101}$ で失敗する．
:::
