# 制約・割当・充足可能性

[第4回へ戻る](../session-04) · [用語ガイド](./) · [前提知識と補助教材](../foundations)

更新日：2026年9月27日

## 「計算せよ」から「関係を満たせ」へ

$t=x^2$ をプログラムの代入として読むと，$x$ から $t$ を計算する指示になる。制約として読むと，すでに並べられた $x,t$ が等式を満たすかという条件になる。**値を計算する処理と，値の関係を強制する制約は別物**である。

変数すべてに値を与えたものを**割当**という。すべての制約を同時に満たす割当が存在するとき，その制約系は**充足可能**である。

## 第4回の例を最後まで書く

$\mathbb F_{101}$ 上で公開出力 $y=35$ を固定する。

$$x\cdot x=t,\qquad t\cdot x=s,\qquad (s+x+5)\cdot1=y.$$

$(x,t,s)=(3,9,27)$ は三つの制約を満たす。最後の条件を消すと，$x=2,t=4,s=8$ も残りを満たす。しかし $8+2+5=15$ であり，公開出力35の主張を示せない。**制約が足りないと，意図しない割当を受け入れる。**

## ブール値と整数の範囲

体上では $b(b-1)=0$ によって $b$ を0または1に制限できる。ANDは $c=ab$，NOTは $c=1-a$ と表せるが，入力がビットであることを合わせて保証する必要がある。

整数 $x$ を $k$ ビットで表したければ，$x=\sum_{i=0}^{k-1}2^i b_i$ と各 $b_i(b_i-1)=0$ を使える。整数の表現を一意に扱うには $2^k<p$ など，法 $p$ と範囲の関係も確認する。加算や乗算の整数としての結果を主張する場合は，結果側の範囲や桁あふれも別途検討する。

たとえば $\mathbb F_7$ では $6+3=2$ である。整数としての $6+3=9$ と矛盾するのではなく，主張している演算の領域が違う。

## 算術化は何を保存するか

正しい翻訳には，元の計算が正しければ満たす割当を作れることと，満たす割当から元の計算の正しさが分かることの両方向が必要である。後者を失うと，不正なウィットネスでも制約を通ってしまう。R1CSはこの制約の書き方の一つであり，それ単独で秘匿や証明の簡潔性を与えるわけではない。

## 確認問題

なぜ加算も $(a+b)\cdot1=c$ というR1CS制約で表せるのか。

::: details 解答
$a+b$，1，$c$ はいずれも変数ベクトルの線形結合である。加算を他の式へ吸収できる場合もあるが，独立した出力変数 $c$ の整合性を保つ必要があるなら制約を残す。
:::
