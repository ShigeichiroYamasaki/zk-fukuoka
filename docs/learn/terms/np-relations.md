## まず「何を確かめるか」を決める

「計算が正しい」というだけでは，何を証明するのか定まらない．たとえば「$x^3+x+5=35$ を満たす $x$ を知っている」という主張を考えよう．35は相手にも知らせる値であり，$x$ は証明者が持つ値である．この二つを分けると，検査すべき条件が見えてくる．

ここでは記号の混同を避け，公開入力を $u$，ウィットネスを $w$ と書く．**関係 $R$ は，組 $(u,w)$ が条件を満たすかを決める規則**である．たとえば有限体を固定し，$R(u,w)=1$ を $w^3+w+5=u$ と定める．$\mathbb F_{101}$ では $(u,w)=(35,3)$ がこの関係を満たす．

## NP関係の定義を読む

通常のNP関係では，$R(u,w)$ を決定的な多項式時間で検査でき，有効なウィットネスのビット長には $|u|$ の多項式による上限を置く．対応する言語は

$$L_R=\{u\mid \exists w:\ R(u,w)=1\}$$

である．関係は「どの組が正しいか」，言語は「正しいウィットネスが存在する公開入力はどれか」を表す．多項式時間の意味は[計算量のページ](./complexity)で確認できる．固定された小さい体の例は定義の読み方を示す教材であり，困難な問題の実例とは限らない．

| 操作 | この例で行うこと |
| --- | --- |
| 探す | $u$ から条件を満たす $w$ を見つける |
| 検査する | 渡された $u,w$ を式に代入する |
| ゼロ知識で証明する | $w$ を直接渡さず，条件が成り立つことを別のプロトコルで示す |

**NPに属するから難しい，という意味ではない．**また，NP関係を書いただけでゼロ知識性や知識の健全性が得られるわけでもない．

## 第4回では何が起きるか

回路はこの検査規則を小さな演算に分ける．制約系は各演算の入力・出力の整合性を要求する．中間変数も，実装上のウィットネスに含まれることがある．何を公開するかは関係の設計時に決めるのであり，「変数だから秘密」とは限らない．

整数について主張したい場合，有限体の等式だけでは足りないことがある．体の演算は法を取るため，整数の範囲や桁あふれの条件も必要になる．[制約と値域](./constraints)へ進もう．

## 確認問題

公開入力を35，中間値を $t=9$，ウィットネスの候補を3とする．「$t=9$ だけ確認する」ことで元の主張を検査できるだろうか．

::: details 解答
できない．少なくとも $t=w^2$ と，さらに $tw+w+5=35$ の対応が必要である．中間値の正しさと公開出力へのつながりを両方制約する．
:::
