## 本講義の位置づけと到達目標

今日で幕II(道具立て)が完結する。これまで断片的に触れてきた計算量理論的な背景——第1回のIP=PSPACE、第4回のCook-Levin定理——を、PCP定理という形で総括し、さらにIOP(Interactive Oracle Proofs)という統一的な枠組みを導入する。この枠組みは、幕IIで学んだ個々の技法(算術化、FRI、コミットメント)が、実際のプロトコルの中でどう組み合わさっているかを理解するための地図になる。

到達目標は次の3点:

1. PCP定理の主張とその歴史的意義を理解する(証明そのものには立ち入らない)
2. 近似困難性研究とのつながりを通じて、PCP定理が計算量理論において独立に重要な結果であることを把握する
3. IOPの枠組みを理解し、これまで学んだ個々の技法(算術化、FRI、コミットメント)が、この枠組みの中でどう位置づけられるかを整理する

## 1. PCP定理:主張と意義

### 1.1 PCPとは何か

Probabilistically Checkable Proof(確率的検査可能証明)とは、証明が特殊な形式で書かれており、検証者がその証明の**ごく一部だけをランダムに読む**ことで、高い確率で正しさを判定できる、という証明の形式である。

### 1.2 PCP定理の主張

> **PCP定理**($\mathrm{PCP}$定理、Arora-Safra 1992、Arora-Lund-Motwani-Sudan-Szegedy 1992):$\mathrm{NP} = \mathrm{PCP}[O(\log n), O(1)]$

これは、任意のNP言語に対して、多項式サイズの証明を用意すれば、検証者はその証明のうち**定数個**の点だけをランダムに読み(かつランダム性は対数ビットしか使わず)、高い確率で正しく判定できる、という主張である。

### 1.3 この定理の驚くべき点

第1回でNPの検証者パラダイムを導入した際、検証者はウィットネス $w$ を**全部**読む必要がある、という前提を確認した。PCP定理は、証明の書き方(エンコードの仕方)を工夫しさえすれば、**検証者は証明のほとんどを読まなくても、高い確率で正しさを判定できる**ことを示している。これは、第1回で問い直した前提(全開示性)とはまた異なる角度から、「証明を全部見る必要はない」という発想を裏付ける、計算量理論における金字塔的な結果である。

*(PCP定理の証明は非常に技術的であり、本講義では扱わない。ここでは結果とその意義の理解にとどめる。)*

## 2. 近似困難性研究とのつながり

### 2.1 なぜPCP定理が近似アルゴリズムの研究と結びつくのか

PCP定理は、当初は純粋に証明系の理論として研究されていたが、意外な形で**近似アルゴリズムの限界**を明らかにする道具になることが分かった。

直感的には、PCP定理の証明の構成そのものが、「ある最適化問題(たとえばMAX-3SATなど)に対して、真の最適値と、それに近い値とを区別することがNP困難である」ということを示す構成に転用できる。これにより、「多項式時間では最適解のある一定割合以上の近似解すら求められない」という**近似困難性(hardness of approximation)**の結果が、PCP定理から導かれることになった。

### 2.2 この事実が伝えること

この事実は、本講義にとって次のような意味を持つ。PCP定理は、SNARK/STARKという応用分野のためだけに存在する道具ではなく、**計算量理論そのものにおいて独立した重要性を持つ結果**である。証明系の設計という実用的な文脈と、近似アルゴリズムの限界という純粋理論的な文脈が、同じ数学的結果によって同時に照らされている、という点は、この分野の学際性を象徴する事実として押さえておきたい。

*(近似困難性の具体的な結果(たとえばMAX-3SATの近似限界の具体的な値)には立ち入らない。ここでは「PCP定理が計算量理論の他分野とも深くつながっている」という位置づけの理解にとどめる。)*

---

## 3. IOP(Interactive Oracle Proofs)による統一的理解

### 3.1 IOPの定義

IOPは、PCPと対話型証明(IP)を組み合わせた枠組みである。証明者と検証者が複数ラウンドにわたって対話し、**各ラウンドで証明者が送るメッセージ全体に対して、検証者はオラクルアクセス(ランダムな一部だけへの問い合わせ)しか持たない**、という設定である。

- PCPは「1ラウンドの証明全体へのオラクルアクセス」
- IPは「複数ラウンドの対話だが、各メッセージは全部読む」
- IOPは「複数ラウンドの対話で、各メッセージへのアクセスもオラクル的(一部だけ)」

という位置づけで整理すると理解しやすい。

### 3.2 これまで学んだ技法をIOPの言葉で振り返る

IOPの枠組みを使うと、幕IIで学んだ技法が次のように整理できる:

- **算術化(第4回)**:計算をIOPで扱える多項式の言葉に変換する前処理
- **FRI(第6回)**:多項式が低次数であることを検査する、IOPの一種(具体的にはIOPP、Interactive Oracle Proof of Proximityと呼ばれる特殊な形)
- **多項式コミットメント(第8回)**:IOPにおける「オラクルへのアクセス」を、実際の暗号学的な手段(ハッシュのMerkle木や、ペアリング)によって実装する仕組み。IOPというやや抽象的な理論的枠組みを、具体的に実装可能なプロトコルへと変換する役割を果たす
- **Fiat-Shamir変換(第9回)**:複数ラウンドのIOPを、最終的に非対話型の証明へと変換する仕上げの工程

つまり、**「IOPを設計する → 多項式コミットメントで実装する → Fiat-Shamirで非対話化する」**という3段階の組み立てが、SNARK/STARKの一般的な設計パターンである、とまとめることができる。この見取り図を持つことで、幕IIIで個別のプロトコル(Groth16/PLONK/STARK)を読む際に、「このプロトコルはこの3段階のどこで何を工夫しているのか」という観点から統一的に理解できるようになる。

### 3.3 STARKとSNARKの違いをIOPの言葉で言い直す

第8回で見たKZG系とFRI系の違いも、このIOPの枠組みで整理し直せる。KZG系(Groth16/PLONK)は、算術化(QAP/PLONKish)から得られる多項式関係を、ペアリングベースのコミットメントで実装する。FRI系(STARK)は、AIRから得られる多項式関係を、FRIベースのコミットメントで実装する。**算術化の選択とコミットメントの選択は、原理的には独立した設計判断であり、両者の組み合わせによって多様なプロトコルが構成されうる**、という視点をここで得ておくと、幕IIIでの理解、さらに今後の研究動向の理解にも役立つ。

## まとめと次回予告

今日学んだこと:

- PCP定理:NPの証明が、証明のごく一部だけの確率的な読み取りで検証可能な形にエンコードできるという、計算量理論の金字塔的結果
- 近似困難性研究とのつながり:PCP定理が証明系の理論だけでなく、近似アルゴリズムの限界を明らかにする独立した重要性を持つこと
- IOPの枠組み:PCPと対話型証明を統合し、幕IIで学んだ技法(算術化・FRI・コミットメント・Fiat-Shamir)を「IOPの設計 → 実装 → 非対話化」という3段階として統一的に整理できること

これで幕II(道具立て)が完結した。次回(第11回)から幕III(統合)に入る。まずGroth16を取り上げ、ペアリングとQAPを組み合わせて簡潔性をどう達成したか、なぜトラステッドセットアップが必要になったかを、今日整理した3段階の見取り図に沿って読み解いていく。

## 講義中に使える発問例

- PCP定理の主張を提示する前に、「証明の書き方を工夫することで、検証者が読む量を減らせると思うか」を予想させると、定理の非自明さが際立つ
- PCP、IP、IOPの3つの枠組みを表に整理させ、それぞれの「検証者が持つアクセス能力」の違いを自分の言葉で説明させる演習が効果的
- 3.3節の「算術化とコミットメントの独立性」について、「では他の組み合わせ(たとえばAIRとKZGの組み合わせ)は可能か」を問いかけ、設計空間の広がりを意識させる
