## 本講義の位置づけと到達目標

前回はペアリングという代数的道具を、第6回ではFRIという符号理論的道具を整備した。今日はこの2つの系統を合流させ、**多項式コミットメント**という、証明系の中核をなす構成要素を扱う。多項式コミットメントは、KZG(ペアリングベース)とFRIベースの2種類を扱い、いずれも背後にある**暗号学的コミットメントスキーム**という一般的な枠組みの具体例として位置づける。

到達目標は次の3点:

1. 暗号学的コミットメントスキームの一般的な安全性定義(binding性・hiding性)を理解する
2. KZGコミットメントの構成と、その安全性がペアリング・q-SDH仮定にどう対応するかを理解する
3. FRIベースのコミットメントの構成と、その安全性が第6回のLow-Degree Testingにどう対応するかを理解する

## 1. 暗号学的コミットメントスキームの一般論

### 1.1 動機:トランプのカードのアナロジー

コミットメントスキームの直感は、「伏せて置いたカード」に喩えられる。ある値 $v$ を「伏せて置く」ことで、(a)相手はカードを見ない限り $v$ が何かを知ることができず(隠蔽性)、(b)自分もあとから別のカードにすり替えることができない(拘束性)、という2つの性質を同時に実現したい。

### 1.2 形式的な構成要素

コミットメントスキームは一般に次の2つのアルゴリズムからなる:

- $\mathrm{Commit}(v, r) \to c$:値 $v$ と乱数 $r$ からコミットメント $c$ を生成する
- $\mathrm{Open}(c, v, r)$:コミットメント $c$ が値 $v$(と乱数 $r$)に対応することを検証する

### 1.3 Binding性

**拘束性(binding)**:一度コミットした値を、あとから別の値にすり替えることができない、という性質。形式的には、同じ $c$ に対して $(v_1, r_1)$ と $(v_2, r_2)$($v_1 \ne v_2$)の両方を開示できるような敵対者が存在しないことを要求する。

### 1.4 Hiding性

**隠蔽性(hiding)**:コミットメント $c$ だけからは、値 $v$ に関する情報が(統計的または計算量的に)漏れない、という性質。

### 1.5 多項式コミットメントへの拡張

多項式コミットメントは、この一般的な枠組みを「値 $v$ が多項式 $f(X)$ である」場合に拡張したものであり、さらに次の追加機能を持つ:

$$\mathrm{Eval}(c, x, y, \pi) \to \{0, 1\}$$

すなわち、コミットした多項式 $f$ について、「$f(x) = y$ である」ことを、多項式全体を開示することなく、短い証明 $\pi$ によって検証可能にする。この追加機能こそが、SNARK/STARKでコミットメントが果たす役割の核心である:証明者は算術化(第4回)によって得られた多項式をまずコミットし、検証者が要求するランダムな評価点についてのみ、その値を効率的に開示する。

## 2. KZG(Kate)コミットメント

### 2.1 セットアップ

トラステッドセットアップにより、ある秘密の値 $\tau$(誰にも知られてはならない)に対して、構造化参照文字列(SRS)

$$\{g, g^\tau, g^{\tau^2}, \dots, g^{\tau^d}\}$$

が生成される。$\tau$ 自体はセットアップ終了後に破棄される(あるいは複数者による分散生成によって誰も単独では知らない状態にされる)。

### 2.2 コミット

多項式 $f(X) = \sum_i a_i X^i$(次数 $d$ 以下)に対して、コミットメントは

$$C = g^{f(\tau)} = \prod_i (g^{\tau^i})^{a_i}$$

として計算される。SRSに含まれる $g^{\tau^i}$ の線形結合として計算できるため、$\tau$ そのものを知らなくても計算可能である点に注意する。

### 2.3 開示と検証:ペアリングの役割

証明者が「$f(x) = y$」を証明したいとき、$f(X) - y$ が $(X - x)$ で割り切れることを利用する(第3回・第5回で扱った、根に関する多項式の基本性質)。商多項式 $q(X) = (f(X) - y)/(X-x)$ を計算し、そのコミットメント $\pi = g^{q(\tau)}$ を証明として送る。

検証者は、前回学んだペアリングを使って次を確認する:

$$e(C \cdot g^{-y}, g) = e(\pi, g^{\tau} \cdot g^{-x})$$

これは $f(\tau) - y = q(\tau) \cdot (\tau - x)$ という関係を、ペアリングの双線形性(第7回)を通じて、$\tau$ を明かすことなく確認していることに相当する。**前回強調した「乗法的な検証能力」が、ここでまさに実際の役割を果たしている。**

### 2.4 安全性の根拠

KZGコミットメントのbinding性は、前回学んだq-SDH仮定に帰着して証明される。異なる多項式に同じコミットメントを与えられる敵対者が存在すれば、q-SDH問題を解くアルゴリズムを構成できる、という還元証明(第7回)の形を取る。

## 3. FRIベースの多項式コミットメント

### 3.1 発想の違い:トラステッドセットアップなしの構成

KZGはトラステッドセットアップ(誰にも知られてはならない $\tau$ の生成)を必要とする。これに対しFRIベースのコミットメントは、第6回で学んだLow-Degree Testingの技法をそのまま応用することで、**トラステッドセットアップを必要としない(transparent)**構成を実現する。

### 3.2 構成の概略

証明者は多項式 $f$ の評価点表現をMerkle木としてコミットする(評価点での値をハッシュ木にまとめ、そのルートを送る)。開示の際は、要求された評価点に対応するMerkle木の経路を提示することで、特定の値がコミットされた表に含まれていることを証明する。

多項式が実際に低次数であることの保証は、第6回のFRIプロトコルをそのまま適用することで得られる。すなわち、「コミットされた表が低次数多項式の評価点表現に近い」ことをFRIで検査し、特定の点での開示をMerkle経路で検証する、という2つの技法の組み合わせである。

### 3.3 安全性の根拠

FRIベースのコミットメントのbinding性は、Merkle木のハッシュ関数の衝突耐性(collision resistance)と、第6回のFRIの健全性に帰着する。ペアリングのような代数的仮定ではなく、**ハッシュ関数の一般的な性質のみに依存する**という点が、KZGとの決定的な違いである。これはSTARKが「ポスト量子安全性」を主張する根拠の一つでもある(楕円曲線の困難性は量子アルゴリズムにより効率的に解けることが知られているが、適切に設計されたハッシュ関数の衝突耐性はそうではないと考えられている)。

## 4. KZGとFRIベースの比較

| | KZGコミットメント | FRIベースのコミットメント |
|---|---|---|
| 基盤となる道具 | ペアリング(第7回) | Low-Degree Testing / FRI(第6回) |
| トラステッドセットアップ | 必要(SRSの生成) | 不要(transparent) |
| 安全性の根拠 | q-SDH仮定への還元 | ハッシュ関数の衝突耐性 + FRIの健全性 |
| 証明サイズ | 定数サイズ | 対数サイズ(FRIの段階数に依存) |

この比較表は、幕IIIでGroth16/PLONK(KZG系)とSTARK(FRI系)を対比する際の設計思想の違いの核心部分にあたる。トラステッドセットアップの要否というトレードオフは、単なる実装上の詳細ではなく、それぞれのプロトコルが依拠する暗号学的仮定の性質そのものの違いに根ざしている、という点を強調しておきたい。

## まとめと次回予告

今日学んだこと:

- 暗号学的コミットメントスキームの一般的な安全性定義:binding性(すり替え不可能性)とhiding性(秘匿性)
- 多項式コミットメントが、コミットメントの一般論に「特定の点での値を効率的に開示できる」という追加機能を加えたものであること
- KZGコミットメント:ペアリングとq-SDH仮定に基づく、トラステッドセットアップを要する構成
- FRIベースのコミットメント:第6回のFRIとハッシュ関数の衝突耐性に基づく、トラステッドセットアップ不要の構成
- 両者の比較を通じて、SNARK系とSTARK系のプロトコルが依拠する暗号学的仮定の性質の違いを把握した

次回(第9回)は、Fiat-Shamir変換を扱う。これまで対話型として組み立ててきたプロトコルを、実際に使える非対話型の証明に変換する仕組みと、その安全性証明の基盤となるRandom Oracle Model、そしてこのモデルが持つ理論的な限界についても議論する。

- コミットメントの一般論を導入する際、「なぜbindingとhidingという一見矛盾しそうな2つの性質が両立できるのか」を問いかけると理解が深まる
