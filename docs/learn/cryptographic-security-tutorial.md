# 暗号学の安全性：ZKを読むための基礎チュートリアル

著者：山崎重一郎  
作成日：2026年9月29日  
最終更新日：2026年9月29日

暗号学では，「安全そうだ」という印象ではなく，**何を守り，誰がどの能力で攻撃し，失敗をどの確率まで許すか**を定義してから方式を評価する．このページでは，安全性パラメータ，確率的多項式時間の攻撃者，安全性ゲーム，計算量的仮定，還元証明を整理し，ゼロ知識証明や多項式コミットメントの性質につなげる．

説明と例題は本サイト向けに独自に作成した．体系的に学ぶための参考書として，Jonathan Katz と Yehuda Lindell の [*Introduction to Modern Cryptography*（著者の案内ページ）](https://www.cs.umd.edu/~jkatz/imc.html) を挙げる．同書は現代暗号を計算機科学の視点から定義・仮定・安全性証明に基づいて扱う．本ページは同書の本文を転載・翻案するものではなく，本講義に必要な概念を独自の説明でまとめる．

## 1. 安全性を定義する

暗号方式の安全性を議論するときは，少なくとも次を明確にする．

1. **対象**：署名，暗号化，コミットメント，証明プロトコルなど，何の方式か
2. **攻撃者の目的**：秘密を知る，新しい署名を偽造する，コミットを後から変える，偽の言明を受理させる，など何を達成したいか
3. **攻撃者の能力**：どの入力やオラクルにアクセスでき，どの情報を知っているか
4. **成功条件**：どの出力が得られたら攻撃成功と数えるか
5. **資源と確率**：計算時間や問い合わせ回数をどう制限し，成功確率をどう測るか

この定義を実験として書いたものを**安全性ゲーム**と呼ぶことが多い．ゲームの実行に使う乱数も含めて攻撃者の成功確率を定め，その確率が小さいことを示す．「攻撃者が何をしたら勝ちか」が定義されていないままでは，安全性の主張も評価できない．

## 2. 安全性パラメータと効率的な攻撃者

安全性パラメータを $\lambda$ と書く．これは鍵長や群の位数など，安全性を高めるために増やせる方式の規模を表す．暗号学では，攻撃者の計算時間を $\lambda$ の多項式で抑える**確率的多項式時間（PPT）攻撃者**を標準的なモデルとして考える．確率的とは攻撃者自身も乱数を使えること，多項式時間とは計算資源が現実的な拡大の仕方に制限されることを表す．

関数 $\epsilon(\lambda)$ が**無視できる**とは，任意の正の整数 $c$ に対して，十分大きな $\lambda$ では $\epsilon(\lambda)<1/\lambda^c$ となることをいう．概念的には，安全性パラメータを大きくすれば，攻撃成功確率がどの逆多項式よりも速く小さくなるという意味である．有限のパラメータで「確率が厳密にゼロ」と主張するものではない．

方式 $\Pi$ が安全であるという表現は，通常「指定した攻撃目標に対し，どのPPT攻撃者も無視できる成功確率しか持たない」という形で読む．安全性は方式の目的と攻撃者モデルに相対的であり，単独の形容詞ではない．

## 3. 計算量的仮定と還元

暗号方式の安全性は，多くの場合，ある計算問題がPPTアルゴリズムには難しいという**計算量的仮定**に基づく．たとえば離散対数問題では，群の生成元 $g$ と $g^x$ から指数 $x$ を求めることが難しいと仮定する．仮定は数学的な定理として確立された事実ではなく，対象の群やパラメータを定めたうえで採用する根拠である．

**還元証明**の基本形は次の通りである：

> もし方式を破る効率的な攻撃者 $\mathcal A$ がいたなら，その攻撃者を部品として利用し，仮定した困難問題を解く効率的なアルゴリズム $\mathcal B$ を構成できる．

従って，困難問題を効率的に解けないという仮定のもとでは，その還元が示す範囲で方式を破る攻撃者も存在しにくい．還元の質を評価するときは，前提となる仮定の強さだけでなく，$\mathcal B$ の計算コストや成功確率が $\mathcal A$ からどれほど悪化するか（還元の損失）も確認する．結論は仮定に条件付けられており，無条件の安全性証明ではない．

## 4. 識別ゲームの読み方

安全性ゲームの簡単な形として，攻撃者に二つの候補のどちらかをランダムに選んだ情報を見せ，どちらだったかを当てさせる**識別ゲーム**がある．秘密ビット $b\in\{0,1\}$ を一様に選び，攻撃者に $b$ に応じた情報を渡す．攻撃者が $b$ を当てる確率が $1/2$ を無視できる量以上に上回るなら，その情報から候補を識別できている．

この形式は，方式の性質を「何が見えるか」「どの二つの世界を区別する力を測るか」として明確にする．コミットメントの隠蔽性では異なるメッセージへのコミットメントを見分けられないこと，ゼロ知識性では実際の対話記録とシミュレータが生成した記録を見分けられないことが，識別不能性の発想に結び付く．

## 5. コミットメントの拘束性と隠蔽性

コミットメントは，値を後から開示できる形で先に固定する仕組みである．安全性は少なくとも二つの別の性質に分けて考える．

- **拘束性（binding）**：一つのコミットメントを，異なる値として有効に開示することができない．
- **隠蔽性（hiding）**：コミットメントを見ただけでは，コミットした値を識別する有意な情報が漏れない．

これらは別々の攻撃ゲームで定義する．方式によっては，乱数が十分なときの完全な隠蔽性ではなく計算量的隠蔽性を満たすなど，保証の強さが異なる．また，拘束性と隠蔽性の両方が自動的に備わるわけではなく，具体的な方式と仮定を確認する必要がある．

多項式コミットメントでは，コミットした多項式 $f$ について，開示値 $y$ と点 $x$ が $f(x)=y$ を満たすかを検証する．KZGでは拘束性が代数的な困難性仮定やセットアップに関係し，FRI/Merkle系ではハッシュ関数の性質と低次数検査の健全性が関係する．同じ「コミットメント」という名前でも，保証の根拠は方式により異なる．

## 6. ゼロ知識証明の三性質を安全性定義として読む

公開入力 $u$ と関係 $R(u,w)$ に対して，証明者は条件を満たすウィットネス $w$ を知っていることを示す．プロトコル $\Pi$ の代表的な性質は次の三つである．

| 性質 | 何を保証するか | 確認する問い |
| --- | --- | --- |
| 完全性 | 正しいウィットネスを持つ証明者は高い確率で受理される | 正直な証明者が不当に拒否されないか |
| 健全性 | 言明を成立させるウィットネスがない場合，受理確率は小さい | 不正な証明者が偽の言明を通せないか |
| ゼロ知識性 | 検証者の観測からウィットネスの情報が漏れない | 実際の対話をウィットネスなしのシミュレータで再現できるか |

各性質は別の条件であり，一つの性質から他の二つが自動的に従うわけではない．特に，完全性は「正しい証明は通る」ことを述べるが，「通った証明の言明が正しい」ことは健全性が扱う．ゼロ知識性は正しさそのものではなく，検証者に何が漏れるかを制限する．

**知識の健全性**を主張する方式では，偽の言明を受理させられないというだけでなく，受理される証明者からウィットネスを抽出できることを要求する．その定義では，抽出者が証明者を実行し，必要なら乱数やチャレンジを制御・巻き戻す能力を持つモデルを明記する．

## 7. 仮定の強さとモデルの境界

安全性証明を読む際には，どの仮定とモデルに依存するかを一覧にする．離散対数のような計算仮定，q-SDHのようなより構造の強い仮定，知識仮定，Random Oracle Model（ROM）のような理想化モデルは，根拠の種類が異なる．これらを単に「暗号学的に安全」とひとまとめにせず，何を仮定した証明かを明示する．

ROMはハッシュ関数を理想的なランダム関数として扱うモデルであり，具体的なハッシュ関数を使う実装そのものの証明ではない．ROMで安全性が示されたという事実と，実装で選んだハッシュ関数の安全性評価は区別する．第9回では，Fiat–Shamir変換におけるこのモデルの利点と限界を詳しく扱う．

## 8. この授業で確認するチェックリスト

プロトコルや安全性証明を読むときは，次を確認する．

1. 守る対象と攻撃者の成功条件は何か
2. 攻撃者はどの入力，乱数，オラクルにアクセスできるか
3. 成功確率はどの乱数について測り，パラメータ $\lambda$ にどう依存するか
4. 安全性はどの困難性仮定，セットアップ，理想化モデルに条件付けられているか
5. 還元はどの攻撃者をどの困難問題の解法へ変換し，どの程度の損失を伴うか
6. 完全性，健全性，知識の健全性，ゼロ知識性のどれを証明しているか

## 練習問題

**練習1**：ある方式について「正しい入力なら証明者は高確率で受理される」とだけ示した．偽の入力が受理されないことまで証明されたと言えるか．

**答え**：言えない．前者は完全性の主張であり，偽の言明への受理確率を抑える健全性は別に証明する必要がある．

**練習2**：拘束性と隠蔽性は，それぞれどの攻撃を防ぐ性質か．

**答え**：拘束性は同じコミットメントを異なる値として開くすり替えを防ぐ．隠蔽性はコミットメントから値を見分けることを防ぐ．別の攻撃なので別々に評価する．

**練習3**：還元証明が「方式の安全性を無条件に証明した」と言えないのはなぜか．

**答え**：安全性の結論が，還元先の困難問題が効率的には解けないという計算量的仮定に条件付けられているためである．
