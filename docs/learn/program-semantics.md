# プログラムの意味：算術化を読むための前提

更新日：2026年10月13日

[前提知識と補助教材](./foundations) · [第4回：算術化](./session-04) · [用語ガイド：実行トレース](./terms/execution-traces)

このページは，第4回の予習に必要な最小限のプログラム意味論を整理する．形式意味論の専門知識ではなく，「プログラムが何を計算するのか」と「その計算がどのような手順で進むのか」を分けて説明し，その意味を回路や代数的制約へ移すときに何を保つべきかを理解することを目指す．

## 1．プログラムを入出力関係として読む

プログラム $P$ に入力 $x$ を与えたとき，実行が停止して出力 $y$ を返すなら，$P(x)=y$ と書ける．プログラムが正しいかを問うには，許される入力と，その入力に対して期待する出力を先に定める必要がある．例えば「入金合計と出金合計が一致する」という計算なら，入力は入金額・出金額の列で，出力は等しいかどうかの真偽値である．

プログラムを証明する文脈では，公開入力 $x$ に対して，ある補助データ $w$ が条件を満たすことを関係 $R(x,w)$ で表す．対応する言語は $L=\{x\mid\exists w,\ R(x,w)\}$ であり，言明の正しさは「$R(x,w)$ を満たすウィットネス $w$ が存在する」と表せる．ここで $R$ は，単にプログラムを実行した結果だけでなく，入力条件，途中計算，出力条件など，証明したい仕様をまとめた検査可能な関係である．ウィットネス $w$ が秘密の入力そのものの場合もあれば，計算履歴や中間値を含む場合もある．第4回の用語ガイドにある[NP関係・公開入力・ウィットネス](./terms/np-relations)がこの書き方を詳しく説明する．

## 2．表示的意味論：プログラムが表す入出力

**表示的意味論（denotational semantics）**は，プログラムの意味を，入力に対してどの出力を返すかという数学的対象で表す．入力の集合を $X$，出力の集合を $Y$ とし，決定的なプログラム $P$ を

$$\llbracket P\rrbracket:X\rightharpoonup Y$$

という**部分関数**として表す．矢印の $\rightharpoonup$ は，すべての入力で値が定まるとは限らないことを表す．$\llbracket P\rrbracket(x)=y$ は，$P$ が入力 $x$ で停止し，出力 $y$ を返すという意味である．停止しない入力では値が未定義となる．

例えば `t := x*x; y := t+1` の意味は，整数計算なら，定義域を指定したうえで $\llbracket P\rrbracket(x)=x^2+1$ と表せる．ただし，実際のプログラムでは整数の範囲，桁あふれ，除算や例外の扱いも出力や停止条件に影響する．したがって，数式だけでなく，どの入力を許し，どの演算規則を使うかまで仕様に含める．

仕様を関係 $S\subseteq X\times Y$ で表すこともできる．プログラムの正しさは，許された入力について，実行結果 $(x,y)$ が $S$ を満たすこととして定める．ZK証明で使う $R(x,w)$ はさらに，公開入力 $x$ とウィットネス $w$ が，この仕様を満たす出力・秘密データ・計算の中間値などを与えるかを判定する関係である．このため，証明系そのものが正しくても，$R$ の定義に必要な仕様を入れ忘れれば，意図と違う内容を証明することになる．

## 3．操作的意味論：プログラムが進む計算手順

**操作的意味論（operational semantics）**は，プログラムの実行を，計算状態の一歩ずつの変化として定義する．状態には，次に実行する命令の位置と，変数に格納された値などを含める．状態 $c$ から $c'$ へプログラム $P$ の一ステップで進めることを

$$c\longrightarrow_P c'$$

と書く．複数ステップの実行はこの遷移を繰り返した列であり，停止状態 $c_{\mathrm{halt}}$ に到達したとき，その状態から出力を取り出す．

例えば `t := x*x; y := t+1` では，入力 $x$ を含む初期状態から，まず $t=x^2$ を格納した状態へ進み，次に $y=t+1$ を格納した停止状態へ進む．この計算の遷移列が，表示的意味論の $\llbracket P\rrbracket(x)=x^2+1$ に対応する．入金合計と出金合計の場合は，状態を二つの累積値 $(s_i,t_i)$ とし，

$$s_0=t_0=0,\qquad s_{i+1}=s_i+d_i,\qquad t_{i+1}=t_i+w_i$$

を各ステップの遷移規則とする．最後に $s_n=t_n$ を判定する．遷移式だけでなく，許される初期状態，読み込む入力，実行回数，終了条件も定めて初めて，意図した計算手順を表す．

表示的意味論は「どの入力・出力が許されるか」を，操作的意味論は「その出力に至る実行が正しいか」を明らかにする．算術化では，両者の対応を保つ必要がある．

## 4．固定した計算をブール回路へ展開する

プログラムの実行を回路で表すには，扱う入力の長さや各値のビット幅，実行するステップ数に上限を定める．この条件のもとでは，計算を有限個の論理ゲートをつないだブール回路として表せる．ブール回路は，0と1を入力・出力とし，AND・OR・NOTなどのゲートで計算する固定されたネットワークである．ゲートとゲートの間の値はワイヤと呼ばれ，途中計算の値を運ぶ．

入金額と出金額の合計を比べる例では，まず各金額を固定ビット幅のビット列として受け取る．二進加算を全加算器の組合せで展開し，桁ごとの和と桁上がりをワイヤに置く．入金の合計と出金の合計ができたら，各ビットを比較し，すべての桁が一致したときだけ出力ビットを1にする．このように，通常のプログラムで一つの加算や比較として書く処理も，回路では有限個の小さなゲートに分解される．合計が収まる幅もあらかじめ確保し，桁あふれによって異なる合計を同じ値と誤認しないようにする．

条件分岐は，条件ビットに応じて二つの値のどちらかを選ぶ選択回路（マルチプレクサ）として表せる．回数に上限のあるループは，その回数分だけ処理の回路を並べる（展開する）．したがって，入力長やループ回数に上限がないプログラムを，サイズの決まった一つの回路でそのまま表すことはできない．入力サイズや実行ステップ数ごとに回路を用意するか，実行トレースのように各ステップの状態を表す方法を使う．

| プログラム上の処理 | 回路での表現 |
| --- | --- |
| 固定幅の整数加算 | 各ビットの加算ゲートと桁上がりのワイヤ |
| 条件分岐 | 条件ビットで出力を選ぶ選択回路 |
| 上限回数のループ | 各反復に対応する回路を順につなぐ |
| 計算結果の正しさ | 出力ビットが期待する値になること |

この回路化は，プログラムの操作的な計算手順を有限個の論理ゲートに展開し，その出力が表示的に定めた関数と一致するようにする段階である．例えば固定幅の整数入力 $x$ に対する `t := x*x; y := t+1` は，表示的には「$y=x^2+1$ を返す」計算であり，操作的には乗算で $t$ を作り，その後に1を加えて $y$ を作る計算である．回路では乗算器・加算器のゲートと，それらを結ぶ中間ワイヤで表す．第4回では，回路の入力・中間ワイヤ・出力の関係をR1CSなどの代数的制約に表す．有限体上の変数 $x,t,y$ を使う単純な形なら，$x\cdot x=t$ と $t+1=y$ が対応する制約になる．ビットを有限体の要素として扱うなら，値 $b$ が0または1である条件を $b(b-1)=0$ と書ける．各ゲートの入出力関係も制約にし，公開入力や出力条件と合わせて，正しい計算だけが制約を満たすようにする．

ただし，この式が通常の整数計算と同じ意味になるとは限らない．有限体では演算結果が法で折り返すため，整数の仕様を証明したいなら，入力・中間値の範囲やビット表現も制約しなければならない．例えば整数の $x^2+1$ を示すつもりでも，範囲条件なしに有限体上の式だけを置けば，表示的に意図した整数関数とは異なる計算を証明している可能性がある．また，分岐条件や停止条件が欠けると，操作的に許されない実行を制約系が受け入れることがある．算術化は式を書き換えるだけではなく，ソースプログラムの意味を保持する作業である．

## 5．実行トレースとAIR

実行トレースは，初期状態から終了状態までを時刻順に並べた表である．各行は一つの時刻の状態を表し，隣り合う行が遷移規則を満たす．

| 時刻 | 入力 | 累積入金 $s_i$ | 累積出金 $t_i$ |
| ---: | ---: | ---: | ---: |
| 0 | — | 0 | 0 |
| 1 | $d_0=4,\ w_0=2$ | 4 | 2 |
| 2 | $d_1=3,\ w_1=5$ | 7 | 7 |

AIRは，操作的意味論で記述した状態遷移列を表として符号化し，その列が正しい実行であることを検査する．遷移制約は隣り合う行が一ステップの意味規則を満たすかを，境界制約は初期状態と最終状態が仕様を満たすかを確認する．この制約が成り立つことから，表示的に定めた入力・出力条件が導けるように設計する．遷移式だけでは任意の開始状態や途中で終わる列を許すことがあるため，初期条件・入力の対応・停止時点・最終条件も必要になる．詳しい用語は[実行トレース・状態・遷移と境界](./terms/execution-traces)を参照する．

## 6．意味を制約へ翻訳する

算術化では，計算の途中の値も変数にし，正しい実行に対応する値の組だけが制約を満たすようにする．これは，操作的意味論で定義した正しい実行と，表示的意味論で定義した入出力の意味の両方を，制約系が正確に表すことを求める．例えば関係 $C_P(x,y,w)$ を「入力 $x$，出力 $y$，補助値 $w$ が算術化後の制約をすべて満たす」と定義するなら，次の二方向を確認する．

- $\llbracket P\rrbracket(x)=y$ なら，その実行の中間値を含む $w$ が存在して $C_P(x,y,w)=1$ となる．
- $C_P(x,y,w)=1$ を満たす $w$ が存在するなら，$P$ の意味において $x$ の正しい出力は $y$ であり，その中間値は許された実行を表す．

これはプログラムの意味を算術化へ移す正しさの条件である．SNARKの完全性・健全性は，このように定めた関係 $C_P$ に対する証明系の性質である．したがって，証明系が正しくても，プログラムの仕様から $C_P$ への翻訳が不正確なら，証明は意図したプログラムの正しさを保証しない．

この二方向を確保するには，必要な入力・出力条件，範囲条件，分岐条件，実行回数や終了条件などを省かないことが重要である．有限体で整数を表す場合は，値が法を超えて回り込まないための範囲制約も必要になる．[入金と出金の算術化例](../exercises/session-04#private)では，これらが意味の保持にどう関わるかを具体的に確認できる．
