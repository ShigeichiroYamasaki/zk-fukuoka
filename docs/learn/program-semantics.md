# プログラムの意味：算術化を読むための前提

更新日：2026年9月30日

[前提知識と補助教材](./foundations) · [第4回：算術化](./session-04) · [用語ガイド：実行トレース](./terms/execution-traces)

このページは，第4回の予習に必要な最小限のプログラム意味論を整理する．形式意味論の専門知識ではなく，「プログラムが何を計算したら正しいのか」を入力・出力・状態遷移で説明できることを目指す．

## 1．プログラムを入出力関係として読む

プログラム $P$ に入力 $x$ を与えたとき，実行が停止して出力 $y$ を返すなら，$P(x)=y$ と書ける．プログラムが正しいかを問うには，許される入力と，その入力に対して期待する出力を先に定める必要がある．例えば「入金合計と出金合計が一致する」という計算なら，入力は入金額・出金額の列で，出力は等しいかどうかの真偽値である．

プログラムを証明する文脈では，公開入力 $x$ に対して，ある補助データ $w$ が条件を満たすことを関係 $R(x,w)$ で表す．対応する言語は $L=\{x\mid\exists w,\ R(x,w)\}$ であり，計算の正しさは「$R(x,w)$ を満たすウィットネス $w$ が存在する」と表せる．第4回の用語ガイドにある[NP関係・公開入力・ウィットネス](./terms/np-relations)がこの書き方を詳しく説明する．

## 2．状態と遷移

状態とは，実行の途中で次の処理を決めるために必要な値の集まりである．入金額を順番に足す処理なら，状態を「現在までの累積合計」とできる．遷移規則は，現在の状態と次の入力から次の状態を計算する規則である．

例えば初期状態 $s_0=0$ から入金 $d_i$ を加える処理は $s_{i+1}=s_i+d_i$，出金 $w_i$ を加える処理は別の累積値 $t_{i+1}=t_i+w_i$ で表せる．最後に $s_n=t_n$ を確認する．遷移だけでなく，初期値と終了条件も指定しなければ，意図したプログラムを表したことにならない．

## 3．実行トレースとAIR

実行トレースは，初期状態から終了状態までを時刻順に並べた表である．各行は一つの時刻の状態を表し，隣り合う行が遷移規則を満たす．

| 時刻 | 入力 | 累積入金 $s_i$ | 累積出金 $t_i$ |
| ---: | ---: | ---: | ---: |
| 0 | — | 0 | 0 |
| 1 | $d_0=4,\ w_0=2$ | 4 | 2 |
| 2 | $d_1=3,\ w_1=5$ | 7 | 7 |

AIRは，この表を満たす計算の証拠として扱い，遷移制約で隣接行の正しさを，境界制約で初期値・最終値を検査する．詳しい用語は[実行トレース・状態・遷移と境界](./terms/execution-traces)を参照する．

## 4．意味を制約へ翻訳する

算術化では，計算の途中の値も変数にし，正しい実行に対応する値の組だけが制約を満たすようにする．翻訳の正しさには二方向が必要である．

- プログラムが正しく実行されるなら，対応する変数割当てが制約を満たす（完全性）．
- 制約を満たす割当てがあるなら，それがプログラムの正しい実行を表す（健全性）．

後者を確保するには，必要な入力・出力条件，範囲条件，分岐条件などを省かないことが重要である．有限体で整数を表す場合は，値が法を超えて回り込まないための範囲制約も必要になる．[入金と出金の算術化例](../exercises/session-04#private)ではこの点も具体的に確認できる．

## 予習の確認

1. 入金合計と出金合計の計算で，状態を一つずつ挙げる．
2. 初期値・遷移規則・終了条件をそれぞれ書く．
3. 遷移制約だけでは，どのような誤った実行を許す可能性があるか説明する．

<summary>確認例</summary>

1. 状態は累積入金 $s_i$ と累積出金 $t_i$．
2. 初期値は $s_0=t_0=0$，遷移は $s_{i+1}=s_i+d_i$ と $t_{i+1}=t_i+w_i$，終了条件は $s_n=t_n$．
3. 初期値や終了条件を固定しないと，別の開始状態や不正な出力でも遷移式だけを満たしうる．
