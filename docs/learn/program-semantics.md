# プログラムの意味：算術化を読むための前提

更新日：2026年10月17日

[前提知識と補助教材](./foundations) · [第4回：算術化](./session-04) · [用語ガイド：実行トレース](./terms/execution-traces)

第4回では，プログラムの計算を回路や代数的制約へ置き換える．ZKはゼロ知識（zero-knowledge）の略で，秘密の情報そのものを明かさずに命題の正しさを確かめる証明技術を指す．その準備として，ここではプログラム意味論の基本だけを確認する．難しい形式理論を学ぶのではなく，「何を計算するプログラムか」と「どの手順で計算するか」を分けて考え，変換後にも守るべき意味をつかむことが目的である．

## 1．プログラムを入出力関係として読む

プログラム $P$ に入力 $x$ を与え，実行が停止して出力 $y$ を返したとき，$P(x)=y$ と書く．正しさを確かめるには，まず「どんな入力を受け付けるか」と「その入力に何を返すべきか」を決める．例えば，入金合計と出金合計が一致するか調べるプログラムなら，入力は入金額と出金額の列，出力は「一致する／しない」の判定である．

証明では，公開する入力を $x$，それ以外の補助データを $w$ とする．「$x$ に対して条件を満たす $w$ がある」ことを，検査可能な関係 $R(x,w)$ で表す．そのような $x$ を集めた集合は

$$L=\{x\mid\exists w,\ R(x,w)\}$$

となる．つまり，$x$ が $L$ に属するのは，条件を満たすウィットネス $w$ を少なくとも一つ示せるときである．$R$ には，入力の条件，途中計算，出力条件など，証明したい仕様を含める．ウィットネスは秘密の入力そのものの場合もあれば，計算履歴や中間値を含む場合もある．記号の詳しい意味は，[NP関係・公開入力・ウィットネスの用語ガイド](./terms/np-relations)を参照する．

## 2．表示的意味論：プログラムが表す入出力

**表示的意味論（denotational semantics）**では，プログラムを「入力を受け取り，出力を返すもの」として捉える．入力の集合を $X$，出力の集合を $Y$ とすると，決定的なプログラム $P$ は次の部分関数として表せる．

$$\langle\!\langle P\rangle\!\rangle:X\rightharpoonup Y$$

ここで $\rightharpoonup$ は**部分関数**を表す記号である．すべての入力で出力が定まるとは限らない，という意味だ．$\langle\!\langle P\rangle\!\rangle(x)=y$ なら，$P$ は入力 $x$ で停止して $y$ を返す．停止しない入力では，この関数の値は定義されない．

例えば，次のプログラムを考える．

```text
t := x*x
y := t+1
```

整数の範囲などを決めれば，このプログラムの意味を $\langle\!\langle P\rangle\!\rangle(x)=x^2+1$ と表せる．ただし，実際の計算機では，整数の範囲や桁あふれ，除算，例外の扱いも結果に影響する．そのため，式だけでなく，許される入力と演算のルールも仕様に書いておく必要がある．

仕様は関係 $S\subseteq X\times Y$ で表すこともできる．許された入力に対し，実行結果 $(x,y)$ が $S$ に含まれていれば，その結果は仕様を満たす．ZK証明で使う $R(x,w)$ は，公開入力 $x$ とウィットネス $w$ を合わせて，出力や秘密データ，中間値が仕様どおりかを確かめる関係である．必要な条件を $R$ に書き忘れると，証明系が正しくても，意図とは違う内容を証明してしまう．

## 3．操作的意味論：プログラムが進む計算手順

**操作的意味論（operational semantics）**では，プログラムの実行を，計算状態が一歩ずつ変わる過程として表す．状態には，次に実行する命令の位置や，変数に入っている値などが含まれる．状態 $c$ から $c'$ へプログラム $P$ が一歩進むことを，次のように書く．

$$c\longrightarrow_P c'$$

この式は「状態 $c$ から，プログラム $P$ の規則に従って状態 $c'$ へ進める」という意味である．複数ステップの実行は，この一歩を繰り返した列になる．停止状態 $c_{\mathrm{halt}}$ に着いたら，そこから出力を取り出す．

先ほどのプログラムなら，最初に入力 $x$ を含む状態から，$t=x^2$ を記録した状態へ進む．次に $y=t+1$ を記録した停止状態へ進む．この一連の手順が，表示的意味論で表した $\langle\!\langle P\rangle\!\rangle(x)=x^2+1$ を実現している．

入金合計と出金合計を計算する場合は，状態を二つの累積値 $(s_i,t_i)$ で表せる．

$$s_0=t_0=0,\qquad s_{i+1}=s_i+d_i,\qquad t_{i+1}=t_i+w_i$$

これらが各ステップの遷移規則である．最後に $s_n=t_n$ を調べる．ただし，遷移式だけでは計算を特定できない．初期状態，読み込む入力，実行回数，終了条件もあわせて決める必要がある．

表示的意味論は「何を入力すると何が出力されるか」を示し，操作的意味論は「その結果に至るまでに，どんな計算をするか」を示す．算術化では，この二つが食い違わないように変換する．

## 4．固定した計算をブール回路へ展開する

プログラムを回路で表すには，入力の長さ，値のビット幅，実行ステップ数に上限を決める．この上限のもとで，計算を有限個の論理ゲートからなるブール回路へ展開できる．ブール回路は，0と1を入力・出力とし，AND・OR・NOTなどのゲートで計算する固定のネットワークである．ゲート間をつなぐワイヤが，途中の値を次のゲートへ渡す．

入金合計と出金合計を比べる回路を考える．まず，各金額を決めた桁数のビット列で受け取る．二進加算は全加算器の組合せに分け，桁ごとの和と桁上がりをワイヤで次へ渡す．二つの合計ができたら，対応するビットを比べ，すべて一致したときだけ出力を1にする．通常のプログラムなら一つの「加算」や「比較」と書く処理も，回路では小さなゲートの集まりになる．また，合計が収まる桁数を確保しなければならない．そうしないと桁あふれが起き，異なる合計を同じ値と扱ってしまうおそれがある．

条件分岐は，条件ビットを見て二つの値から一つを選ぶ回路（マルチプレクサ）で表せる．上限回数が決まったループは，その回数分だけ回路を並べて表す．一方，入力長や実行回数に上限がないプログラムを，一つの固定サイズの回路にそのまま収めることはできない．入力サイズや実行回数ごとに回路を用意するか，実行トレースのように各時点の状態を表す方法を使う．

| プログラム上の処理 | 回路での表現 |
| --- | --- |
| 固定幅の整数加算 | 各ビットの加算ゲートと桁上がりのワイヤ |
| 条件分岐 | 条件ビットで出力を選ぶ選択回路 |
| 上限回数のループ | 各反復に対応する回路を順につなぐ |
| 計算結果の正しさ | 出力ビットが期待する値になること |

回路化では，プログラムの計算手順を有限個のゲートに置き換え，回路の出力が仕様どおりになるようにする．例えば，固定幅整数 $x$ に対する `t := x*x; y := t+1` は，「$y=x^2+1$ を返す」計算である．手順としては，まず $t=x^2$ を求め，次に1を加える．回路では乗算器と加算器をつなぎ，中間値 $t$ をワイヤで渡す．

第4回では，こうした入力・中間値・出力の関係をR1CS（Rank-1 Constraint System，ランク1制約系）などの代数的制約で表す．ここでいう有限体は，要素が有限個で，加減乗除（0による除算を除く）ができる数の体系である．有限体上の変数 $x,t,y$ を使うと，この例の制約は $x\cdot x=t$ と $t+1=y$ になる．ビットを有限体の要素 $b$ で表す場合，$b$ が0か1であることは $b(b-1)=0$ で制約できる．各ゲートの関係に加え，公開入力や出力の条件も制約に含める．その結果，意図した計算だけがすべての制約を満たすように設計する．

ただし，この有限体の式が，通常の整数計算と同じ意味になるとは限らない．有限体では値が法を超えると0へ戻るため，整数の計算を証明したいときは，入力や中間値の範囲も制約する必要がある．例えば，範囲条件なしに $x^2+1$ の式だけを置くと，整数の計算ではなく，有限体上で折り返した別の計算を証明することがある．分岐や停止の条件が抜けていれば，本来は許されない実行を制約系が受け入れるかもしれない．算術化とは，式を書き換えるだけではない．元のプログラムが持つ意味を保つ作業である．

## 5．実行トレースとAIR

実行トレースは，プログラムの状態を開始から終了まで順に並べた表である．各行が一時点の状態を表し，隣り合う行の間で遷移規則が成り立つ．

| 時刻 | 入力 | 累積入金 $s_i$ | 累積出金 $t_i$ |
| ---: | ---: | ---: | ---: |
| 0 | — | 0 | 0 |
| 1 | $d_0=4,\ w_0=2$ | 4 | 2 |
| 2 | $d_1=3,\ w_1=5$ | 7 | 7 |

AIR（Algebraic Intermediate Representation，代数的中間表現）は，操作的意味論で表した状態遷移を表にし，正しい実行かどうかを調べる方法である．遷移制約は，隣り合う行が一歩分の計算規則に従っているかを確かめる．境界制約は，最初と最後の状態が仕様どおりかを確かめる．これらの制約から，表示的意味論で定めた入出力条件が導けるように設計する．遷移式だけでは，好きな状態から始めたり，途中で終わったりする列を許す場合がある．そのため，初期状態，入力との対応，終了位置，最終条件も決めておく．用語の説明は[実行トレース・状態・遷移と境界](./terms/execution-traces)を参照する．

## 6．意味を制約へ翻訳する

算術化では，途中の値も変数に加える．そして，正しい実行に対応する値だけが制約を満たすようにする．つまり，制約系は，操作的意味論が定める正しい手順と，表示的意味論が定める正しい入出力の両方を表さなければならない．例えば，$C_P(x,y,w)$ を「入力 $x$，出力 $y$，補助値 $w$ が算術化後の制約をすべて満たす」という関係とする．このとき，次の二つを確かめる．

- $\langle\!\langle P\rangle\!\rangle(x)=y$ なら，その実行の中間値を含む $w$ が存在して $C_P(x,y,w)=1$ となる．
- $C_P(x,y,w)=1$ を満たす $w$ が存在するなら，$P$ の意味において $x$ の正しい出力は $y$ であり，その中間値は許された実行を表す．

これが，プログラムの意味を算術化へ移すときの正しさの条件である．SNARKの完全性・健全性は，関係 $C_P$ に対する証明系の性質だ．したがって，証明系が正しくても，プログラムの仕様を $C_P$ へ誤って翻訳すれば，証明は意図した計算の正しさを保証しない．

この二方向を成り立たせるには，入力・出力，値の範囲，分岐，実行回数，終了条件など，必要な条件を省いてはならない．整数を有限体で扱う場合は，値が法を超えて折り返さないための範囲制約も必要になる．[入金と出金の算術化例](../exercises/session-04#private)で，これらの条件が意味を保つ役割を具体的に確認できる．
