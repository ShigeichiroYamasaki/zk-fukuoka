## 本講義の位置づけと到達目標

前回学んだGroth16は、証明サイズ・検証コストともに優れていたが、「回路ごとにトラステッドセットアップをやり直す必要がある」という実務上の大きな制約を抱えていた。今日はこの制約を克服するために設計されたPLONK(Gabizon, Williamson, Ciobotaru, 2019)を扱う。

到達目標は次の3点:

1. universal setup(回路に依存しないトラステッドセットアップ)への動機と、それを実現する算術化上の工夫を理解する
2. permutation argument(コピー制約の検証手法)の導入経緯を理解する
3. カスタムゲートという発想が、算術化の表現力と効率性にどう寄与するかを理解する

---

## 1. Universal Setupへの動機

### 1.1 Groth16の制約の再確認

前回確認したように、Groth16のSRSはQAPの構造(すなわち回路そのもの)に依存して生成される。回路が1つでも変われば、トラステッドセットアップを最初からやり直す必要がある。これは、多数の異なるアプリケーション(異なる回路)を扱いたい実務者にとって、大きな運用上の負担になる。

### 1.2 望ましい性質:Universal & Updatable

PLONKが目指したのは、次の2つの性質を持つトラステッドセットアップである:

- **Universal(汎用性)**:一度生成したSRSを、事前に定めたサイズの上限内であれば、**どんな回路にも使い回せる**
- **Updatable(更新可能性)**:複数の参加者が逐次的にSRSの更新に参加でき、そのうち1人でも正直であれば安全性が保たれる(第11回で触れたマルチパーティ生成の考え方を、より柔軟な形で発展させたもの)

この目標を達成するために、PLONKはQAPとは異なる算術化の方式(PLONKish arithmetization)を採用する。

---

## 2. PLONKishな算術化

### 2.1 QAPとの発想の違い

QAP(第4回)は、R1CSの制約群を1本の多項式の割り切れ性に集約する際、回路固有の構造(どの変数がどの制約に現れるか)をSRSの生成時に固定的に埋め込んでいた。これがGroth16のSRSが回路依存になる根本的な理由である。

PLONKでは、計算をゲートの列として表現し、**ゲートの種類(加算・乗算など)を選択する「セレクタ多項式」**を導入する。回路固有の情報は、SRSではなく、この選択多項式(証明生成時に証明者が用意する、公開情報)側に押し出される。これにより、SRS自体は回路に依存しない汎用的なものにできる。

### 2.2 具体的な制約の形

PLONKの基本的なゲート制約は、次のような形を取る:

$$q_L(X) a(X) + q_R(X) b(X) + q_O(X) c(X) + q_M(X) a(X)b(X) + q_C(X) = 0$$

ここで $a, b, c$ はゲートの左入力・右入力・出力を表す多項式(トレース)であり、$q_L, q_R, q_O, q_M, q_C$ が回路固有のセレクタ多項式である。たとえば $q_M = 1$、他が適切に設定されれば乗算ゲート、$q_L=q_R=1, q_O=-1$ などとすれば加算ゲートを表現できる。

このように、**「どの計算をするか」という回路固有の情報を、SRSではなくセレクタ多項式という証明者側のデータに分離した**ことが、universal setupを可能にする鍵である。

::: info 補足:セレクタの固定と制約の評価範囲
セレクタと配線の置換は回路から定まる前処理データであり、証明者が証明ごとに自由に選べるものではありません。そのコミットメントを検証鍵に結び付けます。上の式はゲートを表す評価領域の各点で成立させる条件であり、任意の $X$ で恒等的に0となるという意味ではありません。公開入力の項も含めた制約を領域の消失多項式で割り切れる形にします。SRSへの回路情報の埋め込みはGroth16の構成上の選択であり、QAPという表現だけから必然的に決まるわけではありません。[PLONK原論文](https://eprint.iacr.org/2019/953)を参照してください。
:::

## 3. Permutation Argument(コピー制約)

### 3.1 なぜ必要か:配線の一貫性

ゲートの制約(2.2節)だけでは、「ある1つのゲートの出力が、別のゲートの入力として正しく使われているか」という**配線(wiring)の一貫性**を保証できない。R1CSでは変数 $z_i$ が共有される形で自然にこの一貫性が表現されていたが、PLONKishな表現ではゲートごとに独立した列 $a, b, c$ を使うため、同じ値が複数の箇所に正しくコピーされていることを別途保証する必要がある。

### 3.2 Permutation Argumentの発想

この「同じ値が指定された箇所すべてで一致している」という制約を検証するのが、permutation argument(コピー制約の検証)である。基本的なアイデアは、値の集合として見たときに、ある配置とその置換(permutation)後の配置とが**多重集合として一致する**ことを、多項式の言葉で検証することである。

具体的には、第3回で学んだ多項式の性質を応用し、ある値の集合を根に持つ多項式同士が等しいかどうかを、Schwartz-Zippel補題の考え方(第3回)を用いて確率的に検証する、という技法が使われる(積として累積していく多項式を構成し、その多項式が特定の点で目的の値を取ることを確認する、というのが典型的な構成である)。

*(permutation argumentの具体的な多項式構成の導出は技術的に込み入っているため、本講義では発想の骨格——「配線の一貫性を多重集合の一致という形に翻訳し、それを多項式的に検証する」——の理解にとどめる。)*

::: info 補足:値だけでなく位置も符号化する
値を単に並べ替えるだけなら多重集合は常に一致するため、それだけではコピー制約を検査できません。PLONKでは値に位置のラベルを組み合わせ、回路で指定された置換とランダムなチャレンジを用いて積を比較します。これにより「指定された位置同士の値が等しい」ことを検査します。[原論文のpermutation argument](https://eprint.iacr.org/2019/953)を参照してください。
:::

### 3.3 コピー制約が持つ一般的な意義

このpermutation argumentという技法は、PLONK固有のものではなく、「異なる場所に現れる値が同じであることを、多項式の言葉で効率的に検証する」という一般的な問題への解法であり、PLONK以降の多くのプロトコル設計でも再利用される汎用的な技法として位置づけられる。

## 4. カスタムゲートの意義

### 4.1 動機:頻出パターンの効率化

2.2節の基本ゲート(加算・乗算)だけでは、複雑な演算(たとえば楕円曲線上の点演算や、特定のハッシュ関数の内部演算)を表現するために、非常に多くの基本ゲートを組み合わせる必要があり、証明生成のコストが大きくなる。

**カスタムゲート**とは、頻出する複雑な演算パターンを、専用のセレクタ多項式と制約として直接定義してしまう発想である。たとえば「1つのゲートで複数回の乗算と加算を同時に行う」といった、アプリケーション固有の効率的なゲートを設計できる。

### 4.2 表現力と効率性のトレードオフ

カスタムゲートの導入は、算術化の**表現力**(第2回で導入した軸)を、単なる「NP関係を表現できるかどうか」という理論的な話にとどまらず、**「どれだけ効率よく表現できるか」という実務的な軸にまで拡張する**ものである。基本ゲートのみで表現力自体は理論上十分だが(Cook-Levin定理により任意の計算は基本ゲートの組み合わせで表現できる)、証明者の実際の計算コストを大きく左右する実務的な設計判断として、カスタムゲートの重要性を位置づけておきたい。

## 5. 第10回の見取り図に沿った振り返り

再び「IOP設計 → 実装 → 非対話化」の3段階でPLONKを整理する:

- **IOP設計**:PLONKishな算術化(セレクタ多項式によるゲート制約 + permutation argument)が、検証すべき多項式関係を定めている
- **実装**:KZGコミットメント(第8回)を用いて、これらの多項式関係を評価点で効率的に検証可能にする。ここは基本的にGroth16と共通の道具(ペアリングベースのコミットメント)を使っている点に注意したい。ただしPLONKはFRIベースのコミットメントに差し替えることも設計上可能であり(実際にそうした派生プロトコルも存在する)、算術化とコミットメントの選択が独立した設計判断であるという第10回の指摘がここでも活きる
- **非対話化**:Fiat-Shamir変換(第9回)によって非対話化される。Groth16とは異なり、PLONKは対話型のIOPとしてまず設計され、その後Fiat-Shamirで非対話化するという、より第10回の見取り図に忠実な構成を取っている点も対比しておきたい

## まとめと次回予告

今日学んだこと:

- Universal & UpdatableなSetupへの動機:Groth16の「回路ごとのトラステッドセットアップ」という制約の克服
- PLONKishな算術化:セレクタ多項式によって回路固有の情報をSRSから分離する発想
- Permutation argument:配線の一貫性を多重集合の一致として多項式的に検証する技法
- カスタムゲート:表現力の軸を「効率的に表現できるか」という実務的な次元にまで拡張する発想
- Groth16との対比を通じて、算術化とコミットメントの選択が独立した設計判断であること、そして非対話化の経路(トラステッドセットアップ vs Fiat-Shamir)の違いを確認した

## 講義中に使える発問例

- 2.1節の説明前に「回路固有の情報をSRSから追い出すには、どこに押し出せばよいか」を考えさせると、セレクタ多項式という発想の必然性が見えやすい
- Permutation argumentの導入前に、「配線の一貫性、つまり同じ値が複数箇所で使われていることを、どうやって多項式の言葉で表現できそうか」を自由に議論させると、多重集合の一致という発想への橋渡しになる
- 「カスタムゲートを増やしすぎるとどんなデメリットが生じうるか」(SRSサイズや検証の複雑化とのトレードオフ)を考えさせ、設計上のバランス感覚を養う
