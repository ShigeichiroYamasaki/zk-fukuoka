## 本講義の位置づけと到達目標

前回までのGroth16・PLONKはいずれもペアリングとKZGコミットメントに基づく、トラステッドセットアップを要するプロトコルであった。今日扱うSTARK(Scalable Transparent ARgument of Knowledge; Ben-Sasson et al., 2018)は、**トラステッドセットアップそのものを排除する**という設計目標を出発点とし、第5・6回で整備した符号理論的な道具(RS符号、FRI)を全面的に活用して構成される。

到達目標は次の3点:

1. 「トラステッドセットアップの排除(透明性)」という設計目標が、なぜAIR・FRIという技法選択を要請したのかを理解する
2. STARKの全体構成を、第10回の3段階の見取り図に沿って理解する
3. 透明性とその他の性質(証明サイズ、検証コスト、ポスト量子安全性)とのトレードオフを評価できるようになる

::: info 補足:比較する構成の範囲
Groth16はペアリングを使う直接的な構成で、KZGコミットメントを部品として組み込んだプロトコルではありません。ここでのPLONKは原論文のKZGを用いる構成を指します。また、透明性だけからAIR・FRIが唯一の選択として決まるわけではなく、本講義は代表的なAIR・FRI型STARKを扱います。[第11回](./session-11)・[第12回](./session-12)も参照してください。
:::

## 1. 透明性(Transparency)という設計目標

### 1.1 トラステッドセットアップへの不安

第11回・第12回で見たように、Groth16・PLONKはいずれもトラステッドセットアップ(SRS生成時の秘密のトラップドア)に依存していた。この秘密が万が一漏洩すれば、健全性そのものが崩れる。マルチパーティ計算による分散生成(第11回で触れた)はこのリスクを軽減するが、根本的には「誰も秘密を知らない」ことを完全な確証をもって検証することはできない、という本質的な不安が残る。

### 1.2 透明性の定義

**透明性(transparency)**とは、プロトコルのセットアップに一切の秘密情報を必要としない性質を指す。すべてのパラメータが公開のランダム性(たとえば公知のハッシュ関数の出力など、誰でも検証可能な形で生成される値)のみから構成される。

STARKはこの透明性を最初から設計目標として掲げ、その帰結として、ペアリングベースのKZGコミットメント(秘密のトラップドア $\tau$ を必要とする、第8回)を避け、代わりに**ハッシュ関数の衝突耐性のみに依拠するFRIベースのコミットメント**(同じく第8回)を採用する。

## 2. AIRによる算術化の再確認

### 2.1 なぜAIRが選ばれるのか

第4回で学んだように、AIR(Algebraic Intermediate Representation)は計算の実行トレースを出発点とする算術化技法であった。STARKがAIRを採用する理由は、透明性そのものというより、**FRIとの相性の良さ**にある。AIRは計算の各ステップを行として並べたトレーステーブルを多項式として符号化するが、この符号化は本質的に「評価点表現された多項式」であり、これは第5〜6回で整備したRS符号・FRIの対象そのものと自然に一致する。

### 2.2 遷移制約・境界制約の復習と拡張

第4回で導入した遷移制約・境界制約に加えて、STARKの実装では、複数の制約をランダムな線形結合でまとめて1つの多項式にする、という技法がよく使われる。これは第3回のSchwartz-Zippel補題の考え方(多数の条件を、ランダムな重み付き和という単一の条件にまとめて確率的に検査する)の応用である。この講義の中で繰り返し登場してきた「多数の制約を1つの多項式条件に集約する」という発想が、ここでも一貫して使われていることを確認しておきたい。

## 3. STARKの全体構成

### 3.1 概略のステップ

STARKの証明生成は、大まかに次のようなステップで進む:

1. 証明者が計算を実行し、実行トレースを生成する
2. トレースの各列を、評価点集合上で補間して多項式にする(第3回のLagrange補間)
3. 遷移制約・境界制約を、これらのトレース多項式から構成する(第4回のAIR)
4. 制約をランダムな線形結合でまとめ、単一の合成多項式を構成する
5. この合成多項式が実際に低次数であることを、FRI(第6回)で検査する
6. 各評価点の値は、Merkle木によるコミットメント(第8回)で保証する
7. Fiat-Shamir変換(第9回)により、ランダムな線形結合の係数や検査点をハッシュから決定的に導出し、非対話化する

::: info 補足:制約と低次数検査を結び付ける
この一覧は構成要素の整理であり、そのまま通信の順序を表すものではありません。トレースをより大きな領域へ低次数拡張してコミットし、その後にチャレンジを導出します。制約が指定の点で0になることは消失多項式による割り切れ性として表し、商を用いた合成とトレースとの整合性も検査します。FRIの低次数近接性検査だけで計算の正しさが保証されるわけではありません。[STARK原論文](https://eprint.iacr.org/2018/046)を参照してください。
:::

### 3.2 検証コストと証明サイズ

STARKの証明サイズは、FRIの段階数(元の次数の対数)に比例するため、Groth16の定数サイズと比べると大きくなる(実務上は数十KB〜数百KB程度になることが多い)。検証コストも対数のオーダーであり、Groth16の定数時間検証と比べると相対的に大きい。この点は次節のトレードオフの議論で改めて扱う。

## 4. 透明性とその他の性質のトレードオフ

### 4.1 証明サイズ・検証コストのトレードオフ

第8回の比較表を思い出そう。KZG系(Groth16/PLONK)は定数サイズの証明・定数時間の検証を実現する一方、トラステッドセットアップを要する。FRI系(STARK)はトラステッドセットアップを必要としない代わりに、証明サイズ・検証コストが対数オーダーになる。**透明性を得る対価として、簡潔性の一部(定数サイズという理想)を犠牲にしている**、という構造を明確に理解しておきたい。

::: info 補足:計算量の比較条件
3.2節・4.1節の表現は概略です。STARKの証明にはMerkle認証経路も含まれ、問い合わせ回数・安全性パラメータ・構成によってサイズと検証コストが変わるため、一般には多重対数的なコストとして捉え、FRIの段階数だけから単純な対数比例とはいえません。数十KB〜数百KBは原稿中の目安であり、全実装の保証値ではありません。Groth16やKZG型PLONKも公開入力を扱うコストがあり、検証全体が公開入力数によらず定数時間になるわけではありません。これは代表的構成の比較であり、透明性そのものに対する不可能性定理ではありません。
:::

### 4.2 ポスト量子安全性

第8回で予告したように、STARKのもう一つの大きな利点は**ポスト量子安全性**である。Groth16・PLONKの安全性は楕円曲線上の離散対数の困難性(第7回)に依拠しており、これはShorのアルゴリズムにより量子計算機で効率的に解かれることが知られている。一方STARKの安全性はハッシュ関数の衝突耐性にのみ依拠しており、適切に設計されたハッシュ関数は(現在知られている限り)量子計算機に対しても頑健であると考えられている。

::: info 補足:衝突耐性だけでは説明しきれない安全性
Merkle木の拘束性に必要な衝突耐性と、非対話化後の証明系全体の安全性は区別します。後者にはFRIなどの健全性解析と、Fiat-Shamir変換のランダムオラクルモデルにおける議論も必要です。量子攻撃者を考える場合には、量子ランダムオラクルモデルや適切なハッシュ長・パラメータの検討が必要であり、「ハッシュを使えば自動的にポスト量子安全」という意味ではありません。[Fiat-Shamir変換の量子モデルでの安全性に関する研究](https://arxiv.org/abs/1902.07556)も参照してください。
:::

### 4.3 証明者の計算コスト

一般に、STARKはAIRベースの算術化とFFT的な多項式演算(NTT、[第3回](./session-03)で触れた乗法群の構造がここで実務上重要になる)を活用することで、証明者側の計算量も準線形($O(n \log n)$ 程度)に抑えられる設計になっていることが多い。これはR1CS/QAPベースの構成と比べて、特に大規模な計算を証明する際に有利に働く場合がある。

## 5. 第10回の見取り図に沿った振り返り

- **IOP設計**:AIR(第4回)による算術化と、遷移制約・境界制約のランダムな線形結合による集約
- **実装**:FRIベースのコミットメント(第8回)——Merkle木とFRI(第6回)の組み合わせ——によって、多項式関係を透明性を保ったまま検証可能にする
- **非対話化**:Fiat-Shamir変換(第9回)による非対話化

この3段階の構成は、前回のPLONKと基本的な骨格(IOP設計→実装→非対話化)は共通しているが、**「実装」段階での技法選択(ペアリング+KZG vs ハッシュ+FRI)が根本的に異なる**、という点を改めて強調しておきたい。この違いこそが、透明性・証明サイズ・ポスト量子安全性という、これまでの3回で議論してきたすべてのトレードオフの源泉になっている。

## まとめと次回予告

今日学んだこと:

- 透明性という設計目標が、KZGではなくFRIベースのコミットメントを要請したこと
- AIRがFRIとの相性の良さから選ばれていること、遷移制約・境界制約の構成
- STARKの全体構成を7つのステップとして整理し、これまでの回で学んだ道具がどこで使われるかを確認した
- 透明性・証明サイズ・検証コスト・ポスト量子安全性・証明者の計算コストという複数の軸でのトレードオフ

次回(第14回)は、幕III全体の統合回として、Groth16・PLONK・STARKの3つを、幕Iで定義した完全性(completeness)・健全性(soundness)・ゼロ知識性(zero-knowledge)という性質、および幕IIで導入した暗号学的仮定・計算量理論的結果がそれぞれどこで効いているかを、一覧化しながら横断的に振り返る。

## 講義中に使える発問例

- 「トラステッドセットアップに一切頼らずにプロトコルを構成するには、どのような制約が課されるか」を、KZGの構造(第8回)を思い出させながら議論させると、FRI採用の必然性が見えやすい
- 第8回の比較表を再度提示し、「STARKが失うものと得るものは何か」を学生自身にまとめさせる
- 「なぜ楕円曲線ベースの仮定は量子計算機に弱く、ハッシュ関数は(現時点で)そうではないと考えられているのか」を、Shorのアルゴリズムの直感(周期発見)に軽く触れながら議論させると発展的な理解につながる
